- [x] 가로 스크롤이 생기지 않는다 — 모든 폭·화면
- [x] 콘솔 오류가 없다 — 모든 폭·화면
- [x] 로그인 → 달력 → 일정 등록 → 상세 팝업 → 필터가 동작한다 (390px, 1280px)

## 3. 사람이 봐야 하는 것

### 3.1 접속과 권한

- [ ] 편집용 비밀번호로 로그인된다
- [ ] 브라우저를 닫았다 열어도 로그인이 유지된다
- [ ] **나가기** 를 누르면 풀리고 비밀번호 화면으로 돌아간다
- [ ] 조회용 비밀번호로 들어가면 `조회 전용` 표시가 보인다
- [ ] 조회용에서는 카드/경비 막대와 **카드 내역** 메뉴가 보이지 않는다
- [ ] 조회용에서 주소창에 `/card-expenses` 를 직접 쳐도 내용이 보이지 않는다

### 3.2 달력

- [ ] 세 카테고리가 색과 글리프(◆●■)로 구분된다
- [ ] 필터를 끄고 켜면 막대가 사라지고 나타난다
- [ ] 막대를 누르면 상세 팝업이 열린다
- [ ] 한 칸에 일정이 많으면 `+N개 더 보기` 가 나오고, 눌러서 펼쳐진다
- [ ] 이전/다음 달 이동이 매끄럽다
- [ ] **iOS Safari**: 막대를 탭했을 때 한 번에 열린다 (두 번 탭해야 하지 않는다)
- [ ] **iOS Safari**: 주소창이 나타났다 사라질 때 달력이 잘리지 않는다
- [ ] 가로 모드로 돌렸을 때 레이아웃이 깨지지 않는다

### 3.3 일정 등록과 수정

- [ ] 사이드바에서 일정을 등록하면 달력에 바로 나타난다
- [ ] 항목 유형을 바꾸면 가운데 칸의 이름이 바뀐다 (제출 단계 / 담당 연구원 / 구분)
- [ ] 참석 인원을 명단에서 눌러 넣을 수 있고, 명단에 없는 이름도 직접 넣을 수 있다
- [ ] 막대를 끌어 옮기면 저장된다
- [ ] 막대 끝을 잡아 늘이면 기간이 바뀐다
- [ ] **모바일**: 드래그가 스크롤과 충돌하지 않는다 ← 터치에서 가장 깨지기 쉬운 곳
- [ ] 자동 생성된 일정(준비 기간, 카드 지출)에는 수정·삭제 버튼이 없다
- [ ] 날짜 입력칸이 기기의 기본 날짜 선택기로 열린다 (iOS 휠, Android 달력)

### 3.4 과제와 D-Day

- [ ] 과제를 등록하면 준비 기간 막대가 생긴다
- [ ] 마감일이나 준비 기간을 고치면 막대가 따라 움직인다
- [ ] **캘린더에 표시** 를 끄면 막대가 사라진다
- [ ] 달력 위 D-Day 위젯을 누르면 그 날짜로 이동한다
- [ ] 마감 임박 알림이 하루에 한 번만 뜬다 (닫고 새로고침해도 다시 뜨지 않는다)

### 3.5 카드 내역 올리기

**실제 장부 파일로** 해보셔야 합니다. 목 데이터로는 파싱이 확인되지 않습니다.

- [ ] 구글 시트에서 받은 `.xlsx` 를 올리면 미리보기가 뜬다
- [ ] 달별 추가·사라짐·그대로 건수가 실제와 맞는다
- [ ] **사라짐 건수가 예상과 다르면 반영하지 말고 먼저 확인** ← 가장 중요
- [ ] 오류가 있는 달이 `오류로 해당 월 전체 유지` 로 표시된다
- [ ] 문제 행의 시트·행 번호가 실제 파일과 맞는다
- [ ] 반영하면 달력의 카드 막대가 바뀐다
- [ ] 반영 후 최근 업로드 목록에 남는다
- [ ] **모바일**: 파일 선택이 열린다 (iOS 는 파일 앱, Android 는 문서 선택기)
- [ ] 같은 파일을 두 번 반영하려 하면 미리보기를 다시 받으라고 안내한다

### 3.6 접근성 (실기)

- [ ] iOS VoiceOver 로 달력 막대를 훑으면 카테고리와 제목이 함께 읽힌다
- [ ] Android TalkBack 에서도 같다
- [ ] 글자 크기를 기기 설정에서 키워도 레이아웃이 깨지지 않는다
- [ ] 다크 모드로 두어도 화면이 밝은 테마 그대로 나온다 (의도된 동작)

## 4. 이번 QA 에서 고친 것

**메뉴 버튼이 좁은 화면에서 찌그러졌다.** 헤더가 가로 flex 라 390px 에서 이 버튼이
22×34 까지 눌렸습니다. 사이드바를 여는 유일한 수단인데 손가락으로 겨냥하기 어려웠고,
WCAG 2.5.8 의 최소 24px 도 넘기지 못했습니다. `flex: 0 0 auto` 로 고정해 360~1023px
전 구간에서 34×34 를 유지합니다.

## 5. 확인했지만 결함이 아닌 것

기록해 둡니다. 다시 조사하지 않도록.

| 관찰 | 판단 |
| --- | --- |
| 목록의 작은 버튼들이 높이 28px | 라벨 포함 영역은 충분하고 WCAG 2.5.8(24px)을 넘긴다. 더 키우면 목록이 길어진다 |
| 필터 체크박스 자체가 13×13 | 실제 누르는 영역은 라벨 전체로 279×36 이다 |
| 다크 모드에서 밝은 화면 | `color-scheme: light` 로 고정한 의도된 동작. 기기 다크 모드가 입력칸을 뒤집지 않는다 |
| 모바일에서 등록 후 사이드바가 열린 채 남는다 | 연속 등록을 위한 동작. 바깥을 누르면 닫힌다 |
| 자동 테스트에서 "과제 등록 후 달력이 비어 보임" | 목 서버 DB 가 메모리에 있어 **새로고침하면 초기화**된다. 화면 안에서 이동하면 정상 |
